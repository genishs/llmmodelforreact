## 1. 우리가 만드는 것 (한 문단)

**"React 코드를 대신 써주는 AI를, 남의 서버가 아니라 내 노트북에서 직접 학습시켜 돌린다."**

목표는 실무입니다. `egovGeoportal`이라는 실제 프로젝트에 **JavaScript로 짠 화면 파일이 84개** 있는데, 이걸
전부 **TypeScript로 바꿔야** 합니다. 사람이 하면 오래 걸리니, **그 변환을 잘하는 AI**를 만들어 시키자는 겁니다.

- **JavaScript → TypeScript 변환**이 왜 필요한가: TypeScript는 "이 값은 숫자, 저건 글자"라고 **미리 못 박아두는**
  언어라, 실수를 컴파일 단계에서 잡아줍니다. 안정성을 위해 업계가 옮겨가는 방향입니다.
- **왜 내 장비에서**: 남의 AI(ChatGPT 등)에 회사 코드를 올릴 수 없고, 비용도 들고, 무엇보다 **우리 코드 스타일**을
  가르칠 수 없습니다. 내 모델이면 우리 코드로 가르칠 수 있습니다.

## 2. 용어 사전 (이것만 알면 나머지가 읽힘)

### 모델 관련

| 용어 | 쉬운 뜻 |
|---|---|
| **베이스 모델** | 남이 이미 수천억 원어치 학습시켜 공개한 **밑바탕 AI**. 우리는 `Qwen2.5-Coder`(알리바바가 만든 코딩 특화 AI)를 씁니다. 맨땅에서 AI를 만드는 게 아니라, **다 큰 신입사원을 데려와 우리 회사 방식만 가르치는 것**에 가깝습니다. |
| **7B / 14B / 32B / 70B** | 모델 **크기**. B=Billion(10억). "7B"=70억 개의 숫자 손잡이를 가진 모델. **클수록 똑똑하지만 무겁습니다.** |
| **파인튜닝(fine-tuning)** | 그 신입사원에게 **우리 일을 가르치는 과정**. = "학습", "훈련". |
| **LoRA** | 파인튜닝을 **싸게 하는 기술**. 70억 개 손잡이를 다 만지는 대신 **작은 덧붙임 부품만** 학습시킵니다. 비유하면 **모델 본체는 그대로 두고 얇은 "보정 렌즈"만 새로 깎는 것**. 그래서 결과물이 40~160MB로 작습니다. |
| **어댑터(adapter)** | 그 **학습 결과물 = 보정 렌즈 파일**. `models/qwen-react-lora-7b-r6base` 같은 게 다 어댑터입니다. 베이스 모델에 끼워야 작동합니다. |
| **4bit 양자화 / QLoRA** | 모델의 숫자들을 **정밀도를 낮춰 압축**하는 것. 7B 모델이 원래 14GB인데 4bit로 누르면 ~5GB. **작은 GPU에 욱여넣으려고** 씁니다. 사진을 JPEG로 압축하는 것과 비슷 — 약간 손해 보고 크게 가벼워집니다. |
| **bf16 / fp16** | 압축 **안 한**(또는 덜 한) 상태. 정밀하지만 무겁습니다. |

### 데이터 관련

| 용어 | 쉬운 뜻 |
|---|---|
| **토큰(token)** | AI가 글을 읽는 **단위**. 단어보다 잘게 쪼갠 조각. 대충 **한글 1자 ≈ 1토큰, 영어 4글자 ≈ 1토큰**. "이 파일은 5,000토큰"이면 꽤 긴 파일입니다. |
| **학습 데이터 / 샘플 / 쌍(pair)** | "이런 질문엔 이렇게 답해라"를 모아둔 **교재**. 1쌍 = 문제 1개 + 정답 1개. 우리는 350쌍 정도로 가르칩니다. |
| **`--cap` (오늘의 주인공)** | 교재에 넣을 **문제+정답의 최대 길이 제한**. `--cap 384`면 **384토큰 넘는 교재는 통째로 버립니다.** ← **이게 오늘 밝혀진 모든 것의 원인이었습니다.** |
| **`seq` (시퀀스 길이)** | 학습할 때 AI가 **한 번에 볼 수 있는 최대 길이**. 이걸 넘으면 뒤가 잘립니다. 우리는 768. |
| **held-out (홀드아웃)** | **시험 문제**. 학습에 **절대 안 쓴** 파일들로만 시험을 봅니다. 안 그러면 "교재에서 본 답을 외운 것"과 "진짜 실력"을 구분 못 합니다. **컨닝 방지**가 전부입니다. 우리 시험은 **7문제**(`heldout7`). |
| **과적합(overfitting)** | 교재만 달달 외워서 **시험은 못 보는 상태**. 학원 문제집만 푼 학생이 수능에서 무너지는 것. |

### 측정 관련

| 용어 | 쉬운 뜻 |
|---|---|
| **채점 하니스(harness)** | **자동 채점기**. AI에게 7문제를 풀리고, 나온 코드를 **실제 TypeScript 컴파일러(`tsc`)에 넣어** 에러 개수를 셉니다. 사람이 눈으로 안 봐도 되게. |
| **`tsc`** | TypeScript **컴파일러**. "이 코드 문법·타입 맞냐"를 판정하는 **공인 심판**. 우리 점수의 근거. |
| **`TS18048`, `TS2304` 같은 코드** | tsc가 뱉는 **에러 번호**. 예: `TS2304`="이런 이름 못 찾겠다"(보통 import를 빠뜨림), `TS17008`="문법이 안 닫혔다"(코드가 중간에 끊김), `TS18048`="이 값이 없을 수도 있는데 확인 안 했다". |
| **점수 계산식** | 문제당 `1 - 에러개수/5`, 최저 0점. 즉 **에러 0개=1.0점, 5개 이상=0점.** 7문제 평균 ×100 = 최종 %. |
| **`val_loss` / `eval_loss`** | 학습 중 나오는 **자체 채점 점수**(낮을수록 좋다고 여겨짐). **★그런데 우리는 이게 실제 시험 성적과 거꾸로 가는 걸 실측했습니다.** 아래 시행착오 참조. |
| **분산(variance) / 노이즈 바닥** | **같은 조건으로 두 번 해도 점수가 다르게 나오는 정도.** 시험을 두 번 보면 점수가 조금 다른 것과 같습니다. **이걸 모르면 "5점 차이"가 실력 차이인지 그냥 운인지 알 수 없습니다.** ← **지금 이걸 재고 있습니다.** |
| **seed(시드)** | AI 학습에 쓰이는 **주사위 초기값**. 같은 교재·같은 설정이어도 seed가 다르면 **학습 과정이 미묘하게 달라집니다.** 그래서 **seed만 바꿔 두 번 학습하면 = 순수한 운의 차이**를 잴 수 있습니다. |
| **ablation(어블레이션)** | **하나만 빼보는 실험.** "이 교재 8장이 정말 효과 있나?" → **그 8장만 빼고 똑같이 학습** → 점수가 떨어지면 효과 있었던 것. **범인 색출법**입니다. |
| **n=1, n=2** | **측정 횟수.** n=1 = 한 번만 재봤다 = **믿을 수 없다.** 통계에서 최소 3번, 제대로 하려면 5~10번. |

### 장비 관련

| 용어 | 쉬운 뜻 |
|---|---|
| **4060 / shas** | 이 노트북. **NVIDIA RTX 4060, GPU 메모리 8GB.** 작지만 NVIDIA라 소프트웨어가 잘 돌아감. |
| **8060 / halo** | 다른 장비. **AMD Radeon 8060S(Strix Halo), 메모리 최대 50GB 이상.** 크지만 AMD라 소프트웨어가 자주 깨짐. |
| **GPU 메모리(VRAM)** | AI를 **올려놓을 작업대 크기**. 모델이 여기 안 들어가면 아예 못 돌립니다. **오늘 고생의 절반이 8GB가 좁아서**였습니다. |
| **DirectML / ROCm / CUDA** | GPU에게 일 시키는 **통역기**. CUDA=NVIDIA용(잘 됨), DirectML=Windows용(제한 많음), ROCm=AMD용(까다로움). |

## 3. 지금까지의 이야기 (시간순)

### 3-1. 시작 — "내 노트북에서 되나?"
- 처음엔 **1.5B**(작은 모델)로 시작해서 됐고, **7B**로 올렸습니다.
- **8060(AMD)**에서 먼저 성공. 하지만 **Windows + DirectML 조합이 계속 발목**을 잡았습니다.
- **4060(NVIDIA)**을 투입하니 4bit 압축(QLoRA)으로 **8GB에 7B가 들어갔습니다.**

### 3-2. 두 장비의 경쟁 — 그리고 놀라운 결론
두 장비가 **같은 시험(heldout7)으로 겨루기** 시작했습니다. 통신은 **GitHub**로(각자 자기 파일에만 기록해 충돌 0).

**결과가 예상을 뒤집었습니다:**
- 작은 **7B가 큰 14B를 이겼습니다** (7B 88.6% vs 14B 60~63%).
- → **"모델 크기보다 데이터와 설정이 중요하다"**가 이 프로젝트의 핵심 명제가 됐습니다.

### 3-3. 오늘(7/15) — 오래된 수수께끼를 풀었습니다
**수수께끼**: 옛 챔피언 `r4mlp`가 71.4%인데 새 `r6base`가 88.6%. **왜 17.2점이나 올랐는지 아무도 몰랐습니다.**

**답**: **`--cap` 하나였습니다.**
- 학습인자를 전부 대조해보니 두 어댑터는 **저장 폴더 이름 빼고 완전히 동일**했습니다.
- 유일한 차이가 교재 길이 제한: **384 → 1024**.
- **`cap 384`는 "실제 파일 변환" 교재 10장을 전부 버리고 있었습니다**(전부 384토큰 초과).
- **그런데 시험은 전부 실제 파일 변환입니다.**
- → **시험에 나오는 그 유형의 교재를 한 장도 안 주고 시험을 보게 한 것**이었습니다.

### 3-4. 오늘 밤 — 그런데 더 큰 문제가 나왔습니다
"그럼 왜 그런가"를 파고들다 **이상한 걸 발견했습니다**:
- `cap 384` = 71.4점 → `cap 512` = **60.0점** → `cap 1024` = 88.6점.
- **중간이 더 나쁩니다.** 계단이 아니라 **골짜기**입니다. 어떤 설명으로도 안 맞습니다.
- 그리고 **비슷한 교재로 학습한 두 어댑터가 60점 vs 80점 = 20점 차이**가 났습니다.

**그래서 깨달았습니다**: **우리는 "같은 조건으로 두 번 하면 점수가 얼마나 다른지"를 한 번도 재본 적이 없습니다.**
그러면서 **10~20점 차이를 전부 "이 교재 덕분"이라고 해석해왔습니다.**

**왜 아무도 안 쟀나**: 학습 코드에 **seed(주사위)를 바꾸는 스위치가 아예 없었습니다**(42로 못박혀 있었음).
**잴 수단 자체가 없었던 겁니다.** 오늘 그 스위치를 만들었고, 지금 첫 측정이 돌고 있습니다.

## 4. 시행착오 (여기가 제일 중요합니다)

### 4-1. 프로젝트가 과거에 겪은 것

| 무엇을 믿었나 | 실제로는 | 교훈 |
|---|---|---|
| **"교재를 많이 주면 좋아진다"** | 교재를 늘릴수록 **오히려 나빠짐**(양 장비에서 각각 확인) | **양이 아니라 질·구성.** 핵심 스킬 적정량이 최적점 |
| **"약점을 정조준한 교재를 넣자"** (admin 스킬 10장 추가) | **-14.3점 회귀.** 정조준한 그 admin조차 나빠짐 | **짧은 요약 교재는 독**일 수 있음 |
| **"긴 파일은 잘리니 짧게 쪼개 가르치자"** | 쪼갠 순간 **문제의 본질(파일 전체를 일관되게 변환)이 사라짐**. 이 방침은 오늘 **철회**함 | 자원 제약을 **설계 원칙으로 착각**하면 안 됨 |
| **"AMD gfx1151은 4bit 학습이 안 된다"** | **AMD가 아니라 특정 라이브러리(bnb)가 깨진 것.** 다른 걸 쓰니 3초 만에 통과 | "안 된다"의 **범인을 정확히 지목**해야 함 |
| **"GPU가 리셋되면 하드웨어가 상한다"**(제미나이 경량 모델 경고) | **아닙니다.** GPU 리셋은 **설계된 안전장치**. 전원이 안 끊깁니다. **위험한 건 하드웨어가 아니라 강제 재부팅으로 인한 파일 손상** | **"하드웨어는 안전, 데이터가 위험"**. 경량 AI의 단정은 근거를 앞지름 |

### 4-2. 오늘 **제(PM)가** 틀린 것 — 5번

| # | 제가 한 주장 | 어떻게 틀렸나 | 어떻게 잡혔나 |
|---|---|---|---|
| **1** | 재현 방법을 문서에 적어 발행 | **스크립트를 잘못 지목**(`train_directml` ← 실은 `train_qlora`). 앞의 건 4bit를 못 하는 스크립트 | **직접 돌려보다 GPU 터짐** |
| **2** | "실제 파일 교재 8장이 +17점의 엔진" | **그 8장을 빼도 -3.3점뿐**. 지목한 태스크는 **꿈쩍도 안 함** | **ablation 실험** |
| **3** | "채점이 죽는다, 이 장비론 불가능" (정본에 커밋까지 함) | **살아있었음.** 제가 **껍데기 프로세스**를 감시하다 오판 | **30분 뒤 진짜 프로세스 발견** |
| **4** | GPU가 비었다고 판단하고 학습 투입 | **다른 작업이 GPU를 쥐고 있었음** → 즉사 | 로그 확인 |
| **5** | "egovreal은 엔진이 아니다"를 팀·정본에 발행 | **정반대.** 7문제 중 6문제만 보고 결론냈는데, **하필 그 빠진 1문제가 핵심**이었음. 다 넣으니 **egovreal이 절반을 책임** | 마지막 문제 완주 |

**5번이 가장 부끄럽습니다.** 제가 30분 전에 정본에 **"그 문제 없이 결론 내지 말 것"**이라고 직접 적어놓고 **제가 어겼습니다.**

**공통 패턴**: **그럴듯한 설명이 떠오르면 재보지도 않고 발행했습니다.** 다행히 **5번 다 측정이 잡았고**, 전부 정정과 함께 기록에 남겼습니다.

### 4-3. 그리고 오늘 밤, 팀이 저를 잡았습니다

두목이 **"직접 다 하지 말고 팀에 맡기라"** 하셔서 네 명을 붙였더니, **제가 하루 종일 못 본 걸 짚었습니다:**

- **QA(큐선생)**: *"오늘 헤드라인 결론의 **절반 이상이 `medit`이라는 문제 하나에 의존**하는데, 그건 당신들이
  **'가장 불안정하다'고 스스로 문서에 적어놓은** 바로 그 문제다."*
  → **저는 그 두 사실을 각각 알아내놓고 연결하지 못했습니다.**
- **QA**: 채점기 코드에 **실제 결함** 발견 — **"문법이 아예 깨진 답"과 "사소한 경고 하나"가 같은 감점**입니다.
- **QA**: *"당신 실험 설계도 틀렸다. 의심스러운 건 cap512인데 당신은 멀쩡한 r6base를 재고 있다."*
- **Gemini(쥐선생)**: *"이 팀의 실험 프로그램 전체가 해석 불가능하다. **찻잎점을 치고 있다.**"*
